# Writing and maintaining the docs

The docs live in this repo, under `docs/`, so they version with the code. A code change
that alters behaviour a user or developer can see is not finished until the matching page
is updated. The ownership table in the local `AGENTS.md`
says which page each source area owns, and `node tools/docs/check-docs.mjs` fails when the
docs drift from the code: a studio with no page, a stale generated table, a broken link and
the other checks listed under [Checking](#checking).

## Layout

| Path | Audience | Contents |
|---|---|---|
| `README.md` | everyone | Landing page: what it is, download, quick start, gallery, links into docs |
| `FEATURES.md` | users | One line per feature, each linking to the page that explains it |
| `docs/README.md` | everyone | Index of every page |
| `docs/user/` | users | Getting started, the data folder, Colab, backends, generation, quality, adapters, plugins, model files, MCP, one page per studio, training, presets, troubleshooting |
| `docs/dev/` | contributors and agents | Architecture, building, config, engine and the ggml fork, the API index and contracts, pages for replacement frontends, plugin authoring, training internals, releasing, RunPod, UI design and server state, writing style |
| `.claude/skills/` | agents | Procedures for maintenance tasks (see its README) |
| `docs/plans/` | local only | Gitignored design notes. Distil lasting decisions into `docs/dev/` |

Generated text sits between `<!-- generated:start NAME -->` and `<!-- generated:end NAME -->`
markers, under a `<!-- generated by tools/docs/build-docs.mjs, do not edit by hand -->` line.
Text outside the markers is hand-written and the generator leaves it alone. Edit the source
a block is built from, then run `node tools/docs/build-docs.mjs`. The blocks are:

- `docs/user/plugins.md`: the solver, scheduler, guidance and postprocess tables, from the
  metadata table at the top of each `.lua` under `engine/plugins/` (built in) and `plugins/`
  (community). Files with `_INTERNAL` in the name, or under an `archive` or `debug` folder,
  are skipped.
- `docs/dev/api.md`: the route index and route count, from the `app.use('<prefix>', <router>)`
  mounts in `server/src/index.ts` and the `router.<verb>(` calls in each mounted
  `server/src/routes/<name>.ts` and its `server/src/routes/<name>/` folder, plus the training
  operation domains registered with `registerTrainingOperations()` in `server/src/services/training/`.
- `docs/user/models.md`: the packs table and one file table per model family, from
  `server/src/data/model-registry.json`. A family new to the registry gets its own section
  appended.
- `server/src/data/assistant-knowledge.md`: `backends` (the first paragraph of
  `docs/user/backends.md`), `studios` (the first paragraph of each page in `docs/user/studios/`),
  `troubleshooting` (the "Common problems" section of `docs/user/troubleshooting.md`),
  `data-folder` (all of `docs/user/data-folder.md`) and the `solvers`, `schedulers` and
  `guidance` plugin tables. The in-app assistant reads this file once and caches it, so a
  change reaches it after a restart.

## Rules for every page

Follow [writing-style.md](writing-style.md): sentence case headings, no emojis, no em
dashes, no puffery, straight quotes.

Document only what you can verify in the code, the UI strings (`ui/src/i18n/locales`), or
by running it. Never describe what a control probably does. If you cannot tell, name the
control and where it lives, and leave `<!-- TODO(verify): ... -->` for someone who can.

No artist names, album names or dataset names from private collections. Generic examples
only ("a 90s trip-hop album", not a real one).

Relative links only, to the file: `[Cover Studio](studios/cover-studio.md)`. Anchors are
lowercase-hyphenated heading text.

Screenshots go in `docs/images/` as `.webp`, named `studio-<slug>.webp`. Until the image
exists, keep the image line and a `<!-- screenshot: needed -->` comment so the gap is visible.
The five screenshots already there keep their older `hot-step-<slug>.webp` names.

## Studio page template

```markdown
# <Sidebar name>

<One paragraph: what it is for and when to reach for it.>

![<Sidebar name>](../../images/studio-<slug>.webp)
<!-- screenshot: needed -->

## Where to find it

Sidebar entry, and anything that has to be true first (a backend, a model, a song in the library).

## Workflow

1. Numbered steps for the common path, in the order the UI presents them.

## Controls

| Control | What it does |
|---|---|
| Label as shown in the UI | One or two sentences. Ranges and defaults where they matter. |

## Tips and limits

Short prose or bullets: what trips people up, what the studio does not do.

## Related

- [Other page](../other-page.md)
```

Keep a studio page between 60 and 250 lines. If it needs more, the studio has a
sub-feature that wants its own page.

## Checking

```
node tools/docs/build-docs.mjs      # refresh generated tables
node tools/docs/check-docs.mjs      # exit 1 on drift or broken links
```

`check-docs.mjs` exits 1 on any of these:

1. A generated block is stale. It runs `build-docs.mjs --check`, which writes nothing.
2. A folder in `ui/src/components/` has no row in `STUDIO_PAGES` in `check-docs.mjs`, or its
   page does not exist. Add the row when you add a studio.
3. A folder in `.claude/skills/` is not listed in `.claude/skills/README.md`. Gitignored
   local skills are skipped.
4. A relative link or image in a tracked or new untracked `.md` file does not resolve. Links
   inside code are ignored. A missing gitignored target is only a warning, because local
   agent files are absent from public checkouts, and so is a missing image on a page that
   carries `<!-- screenshot: needed -->`.
5. `FEATURES.md` does not link every page named in `STUDIO_PAGES`.
6. A `.tsx` file under `ui/src` has more native `<select>` or checkbox controls than
   `tools/docs/ui-primitives-baseline.json` allows ([UI design rules](ui-design.md)). The
   baseline only shrinks: after converting a control, run
   `node tools/docs/check-docs.mjs --update-ui-baseline`.

`node server/scripts/check-release-prereqs.mjs` runs `check-docs.mjs`, and so does CI
(`.github/workflows/docs.yml`, on every push to master and every pull request).
